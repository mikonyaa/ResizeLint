# RL002 — main-screen-scale

Default severity: **warning**. Automatic fix: **limited**.

## What it finds

RL002 reports `UIScreen.main.scale` and `UIScreen.main.nativeScale`.

```swift
let pixelWidth = width * UIScreen.main.scale
```

## Adaptive alternative

Prefer the trait environment that owns the rendered content:

```swift
final class CanvasView: UIView {
    func render(width: CGFloat) {
        let pixelWidth = width * traitCollection.displayScale
    }
}
```

A scene-local screen passed from the caller is also valid when the operation genuinely needs screen information.

## Safe fix boundary

`resizelint fix` replaces an exact `UIScreen.main.scale` expression only inside an instance member of a proven UIKit view or view-controller type where `traitCollection` is directly available. It never rewrites `nativeScale`, static members, free functions, or ambiguous types.

The boundary is determined from SwiftSyntax ancestry. Eligible bodies are direct instance methods or property accessors of classes directly inheriting `UIView`, `UIViewController`, `UITableViewCell`, `UICollectionViewCell`, or `UIControl` (including `UIKit.` qualification). The edit is `self.traitCollection.displayScale`, so a local variable named `traitCollection` cannot change its receiver.

Static/class members, subscripts, stored/lazy initializers, initializers/deinitializers, local functions, closures, nested types, extensions, unknown inheritance and recovered syntax receive a diagnostic without an automatic edit. This conservative scope may omit valid fixes. Reparsing checks syntax after editing; it is not semantic type-check proof. Release checks compile independent Swift stubs and separate native UIKit fixtures before and after the edit. Compile and test your application after applying fixes.
